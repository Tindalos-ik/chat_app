# 服务端部署指南

> 覆盖两条部署路径：
> 1. **Windows 本地部署**（开发/联调）
> 2. **Linux 服务器部署**（正式环境）
>
> 涉及四个服务：VarifyServer（Node.js）、StatusServer（C++）、ChatServer（C++）、GateServer（C++）。

---

## 1. 部署架构总览

```text
客户端(Qt)
   │ HTTP(8080)
   ▼
GateServer ──gRPC(50051)──► VarifyServer(Node.js) ──► Redis + SMTP邮箱
   │  gRPC(50052)
   ▼
StatusServer ──► 选择 ChatServer(8090/8091) + 签发 token
   ▲
   │ gRPC(50052) 校验 token
ChatServer(8090 / 8091) ──► Redis / MySQL
```

| 服务 | 语言 | 端口 | 依赖 |
| --- | --- | --- | --- |
| VarifyServer | Node.js | 50051 (gRPC) | Redis、163 SMTP 邮箱 |
| StatusServer | C++ | 50052 (gRPC) | MySQL、Redis |
| ChatServer | C++ | 8090 / 8091 (TCP) | MySQL、Redis、StatusServer |
| GateServer | C++ | 8080 (HTTP) | MySQL、Redis、VarifyServer、StatusServer |

**启动顺序**：MySQL → Redis → VarifyServer → StatusServer → ChatServer1/2 → GateServer。

---

## 2. 前置依赖清单

### 2.1 中间件

- MySQL 8.x（库名按你的配置：`chat_app_db`）
- Redis（默认 6379，需要密码则修改各 config.ini）

### 2.2 编译依赖（C++ 服务）

- Boost 1.91（asio/property_tree，头文件为主）
- gRPC + protobuf（代码生成与运行库）
- redis-plus-plus（CMake target：`redis++::redis++`，底层依赖 hiredis）
- MySQL Connector/C++（X DevAPI，头文件 `<mysqlx/xdevapi.h>`）
- jsoncpp（项目里已内置 `jsoncpp/jsoncpp.cpp`，无需额外安装）

### 2.3 Node.js 依赖（VarifyServer）

`package.json` 里的 `@grpc/grpc-js`、`@grpc/proto-loader`、`ioredis`、`nodemailer`、`uuid`，执行 `npm install` 安装。

## 3. 数据库准备

1. 创建数据库（schema 名要与各服务 `config.ini` 的 `[Mysql] schema` 一致，当前为 `chat_app_db`）：

```sql
CREATE DATABASE IF NOT EXISTS chat_app_db DEFAULT CHARACTER SET utf8mb4;
```

2. 建表并导入初始数据。参考项目的建表脚本在 `llfcchat/sql备份/llfc.sql`（库名 `llfc`、含 `user`、`friend`、`friend_apply` 等表），导入前把里面的库名改成 `chat_app_db`，或直接执行建表语句部分：

```bash
mysql -uroot -p chat_app_db < llfc.sql
```

3. 各服务连接 MySQL 的用户要有远程/本地访问权限，密码与 `config.ini` 一致。

## 4. Windows 本地部署（开发/联调）

### 4.1 构建

项目根目录已配置好 vcpkg 工具链（CMakePresets.json / .vscode）：

```powershell
cd D:\myproject\chat_app
cmake --preset windows-vcpkg        # 配置（VS2022 + vcpkg）
cmake --build --preset debug        # 编译 Debug
```

生成的可执行文件：

```text
build\ChatServer\Debug\ChatServer.exe
build\GateServer\Debug\GateServer.exe
build\StatusServer\Debug\StatusServer.exe
```

`config.ini` 已由 CMake 自动拷贝到各 `Debug` 目录下，**必须在对应的 Debug 目录里启动程序**（ConfigMgr 读取"当前工作目录/config.ini"）。

### 4.2 启动

每个服务开一个终端：

```powershell
cd D:\myproject\chat_app\VarifyServer
npm install        # 首次
npm run serve      # node server.js，监听 50051

cd D:\myproject\chat_app\build\StatusServer\Debug
.\StatusServer.exe     # 监听 50052

cd D:\myproject\chat_app\build\ChatServer\Debug
.\ChatServer.exe       # 监听 8090（再复制一份改端口 8091 跑 ChatServer2）

cd D:\myproject\chat_app\build\GateServer\Debug
.\GateServer.exe       # 监听 8080
```

### 4.3 验证

```powershell
# GateServer HTTP 是否通
curl http://127.0.0.1:8080/get_test

# 各服务控制台输出应显示 "Server listening on ..." / "Server start success..."
# 登录接口：
curl -X POST http://127.0.0.1:8080/user_login -H "Content-Type: application/json" `
  -d '{"email":"test@163.com","passwd":"123456"}'
```

## 5. Linux 服务器部署

以 Ubuntu 22.04/24.04 为例。

### 5.1 安装基础工具

```bash
sudo apt update
sudo apt install -y build-essential cmake git pkg-config
```

### 5.2 安装 C++ 依赖

方案 A：直接用 apt 安装系统包（简单，版本可能略旧）：

```bash
sudo apt install -y libboost-all-dev \
  libgrpc++-dev protobuf-compiler-grpc libprotobuf-dev \
  libhiredis-dev libmysqlcppconn-dev libjsoncpp-dev
```

redis-plus-plus 不在所有发行版仓库里，Ubuntu 24.04 可用 `libredis++-dev`；如果仓库没有，就用方案 B 编译安装：

```bash
git clone https://github.com/sewenew/redis-plus-plus.git
cd redis-plus-plus
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release -DREDIS_PLUS_PLUS_CXX_STANDARD=17
make -j$(nproc) && sudo make install
sudo ldconfig
```

方案 B：统一用 vcpkg（与 Windows 一致）：

```bash
git clone https://github.com/microsoft/vcpkg.git ~/vcpkg
~/vcpkg/bootstrap-vcpkg.sh
~/vcpkg/vcpkg install grpc protobuf redis-plus-plus mysql-connector-cpp boost-asio
```

> 若用 apt 装的 MySQL Connector，头文件可能在 `/usr/include/mysql-cppconn-8`，编译时要把这个目录加进 include path（见 5.4 的 CMake 修改）。

### 5.3 安装 Node.js（VarifyServer）

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
node -v && npm -v
```

### 5.4 上传代码并做跨平台适配

把 `chat_app` 上传到服务器（可以排除 build 和 node_modules）：

```bash
# 本机打包：tar -czf chat_app.tar.gz --exclude=build --exclude=node_modules chat_app
scp chat_app.tar.gz user@服务器IP:/opt/
ssh user@服务器IP
cd /opt && tar -xzf chat_app.tar.gz
```

**必须修改 CMakeLists.txt 才能用 GCC 编译**，三个 C++ 服务的 CMakeLists 都做了 Windows 专用假设：

1. `add_compile_options(/utf-8 /wd4819)` 是 MSVC 参数，GCC 不认识 → 改成按编译器区分：

```cmake
if(MSVC)
    add_compile_options(/utf-8 /wd4819)
else()
    add_compile_options(-Wall)
endif()
```

2. `link_directories("D:/cppsoft/vcpkg/installed/x64-windows/lib")` 是 Windows 绝对路径 → 包在 `if(WIN32)` 里，Linux 让 CMake 通过 find_package 自动找库：

```cmake
if(WIN32)
    link_directories("D:/cppsoft/vcpkg/installed/x64-windows/lib")
endif()
```

3. include 路径里的 `"C:/local/boost_1_91_0"` 和 `"D:/cppsoft/vcpkg/installed/x64-windows/include"` 同样包在 `if(WIN32)` 里；Linux 上 boost 用系统安装的即可。

4. 如果 MySQL Connector 头文件在 `/usr/include/mysql-cppconn-8`，追加：

```cmake
target_include_directories(${PROJECT_NAME} PRIVATE /usr/include/mysql-cppconn-8)
```

> 这三个子项目（ChatServer/GateServer/StatusServer）的 CMakeLists 结构相同，改动方式一致。

### 5.5 编译

```bash
cd /opt/chat_app
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
```

生成：

```text
build/ChatServer/ChatServer
build/GateServer/GateServer
build/StatusServer/StatusServer
```

### 5.6 配置 config.ini

把各服务目录下的 `config.ini` 放到**可执行文件旁边/启动工作目录**（ConfigMgr 从当前目录读 `config.ini`）。关键修改：

```ini
[Mysql]
host = 127.0.0.1        ; 或云数据库地址
passwd = 你的密码
schema = chat_app_db

[Redis]
host = 127.0.0.1
passwd = 你的密码

[StatusServer]
host = 127.0.0.1        ; 服务间通信地址
port = 50052

[ChatServer1]
host = 服务器公网IP       ; 注意！这是返回给客户端的地址，必须客户端能访问
port = 8090
name = ChatServer1
```

> ChatServer 的 `host` 是客户端 TCP 直连地址：如果客户端在外网，这里要填**公网 IP**（或内网穿透地址），不能填 127.0.0.1。

### 5.7 启动服务

```bash
cd /opt/chat_app/build/StatusServer && ./StatusServer &
cd /opt/chat_app/build/ChatServer  && ./ChatServer &      # 8090
cd /opt/chat_app/build/GateServer  && ./GateServer &      # 8080

cd /opt/chat_app/VarifyServer
npm install
npm run serve &
```

更稳妥的方式：用 `systemd` 或 `pm2` 托管（见 5.8），不要裸 `&` 跑生产环境。

### 5.8 进程守护（systemd）

以 StatusServer 为例，创建 `/etc/systemd/system/status-server.service`：

```ini
[Unit]
Description=StatusServer
After=network.target mysql.service redis-server.service

[Service]
Type=simple
WorkingDirectory=/opt/chat_app/build/StatusServer
ExecStart=/opt/chat_app/build/StatusServer/StatusServer
Restart=always
RestartSec=3
User=ubuntu

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now status-server
sudo systemctl status status-server
```

VarifyServer 用 pm2 托管更省心：

```bash
sudo npm install -g pm2
cd /opt/chat_app/VarifyServer
pm2 start server.js --name varify-server
pm2 save && pm2 startup     # 开机自启
```

ChatServer1/2、GateServer 按同样的方式各建一个 service 文件。

## 6. 防火墙与安全组

云服务器（阿里云/腾讯云/AWS）要在**安全组**里放行，同时注意本机防火墙：

```bash
sudo ufw allow 8080/tcp    # GateServer HTTP（客户端访问）
sudo ufw allow 8090/tcp    # ChatServer1 TCP
sudo ufw allow 8091/tcp    # ChatServer2 TCP
sudo ufw allow 50051/tcp   # VarifyServer gRPC
sudo ufw allow 50052/tcp   # StatusServer gRPC
sudo ufw enable
```

建议：50051/50052 属于服务间内部调用，如果所有服务在同一台机器/内网，可以把它们的监听地址配成内网 IP 并只对内部放行，不暴露公网。

## 7. 客户端连接配置

客户端（Qt）有两处服务器地址：

1. **HTTP 网关地址**：`gate_url_prefix`（如 `http://服务器IP:8080`），负责注册/登录/获取验证码；
2. **聊天服务器地址**：登录成功后由 StatusServer 返回的 `host:port`（对应 config.ini 里 ChatServer1/2 的 host），客户端据此发起 TCP 长连接。

因此 Linux 上 ChatServer 的 `host` 必须填客户端可达的 IP；GateServer 的 `[GateServer] host/port` 填监听地址。

## 8. 常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动报 `Config file not found` | 启动目录没有 config.ini | 在可执行文件所在目录启动，或把 config.ini 拷过去 |
| 客户端连不上 GateServer | 8080 未放行 | 检查安全组 + ufw |
| 登录后连不上聊天服务器 | StatusServer 返回的 ChatServer host 是 127.0.0.1 或内网 IP | 改成公网可达 IP |
| gRPC 调用失败/超时 | 50051/50052 不通，或服务未按顺序启动 | 先起 VarifyServer/StatusServer 再起 GateServer |
| MySQL 连不上 | host/端口/密码错误，或 MySQL 未开远程访问 | 检查 config.ini；`mysql -h <ip> -P <port> -uroot -p` 测试 |
| Linux 编译报 `/utf-8` 参数错误 | 没改 CMakeLists 的 MSVC 专属参数 | 按 5.4 改造后再编译 |
| Windows 运行缺 DLL | Debug 目录缺 vcpkg 的 dll | 把 `D:/cppsoft/vcpkg/installed/x64-windows/debug/bin` 下的 dll 拷到 exe 同目录 |
| 验证码一直收不到 | SMTP 授权码错误或 Redis 连不上 | 检查 `VarifyServer/config.js` 的邮箱授权码和 Redis |

## 9. 生产环境安全建议

1. **不要用 root 跑服务**：systemd `User=` 指定普通用户；
2. **gRPC 换 TLS**：现在用 `InsecureChannelCredentials`/`createInsecure()`，公网部署应换成 `SslServerCredentials` + 证书；
3. **密码管理**：config.ini 里明文密码在生产环境应改为环境变量/密钥管理；
4. **最小化端口暴露**：只对外开 GateServer(8080) 和 ChatServer(8090/8091)，内部服务走内网；
5. **数据库备份**：定期 `mysqldump` 备份 `chat_app_db`；
6. **日志**：生产环境把 stdout 交给 systemd journal 或 pm2 日志，方便排查；
7. **多实例**：ChatServer1/2 配置一致、端口不同，StatusServer 自动负载均衡；以后要扩机器，只需把新机器的 config.ini 注册进 StatusServer 的 `_servers` 配置。
